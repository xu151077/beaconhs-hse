## 2. 根因（四类，互相独立）

## 3. 修复

## 10. 角色数据范围「所有人都显示为本人记录」（EA-66D.11）

### 10.1 根因

`scope-picker.tsx` 把选择器的本地状态序列化成 `RoleScope` 时，`switch` 只处理了 `self / sites / crews / people / team`，**漏了 `tenant`**。选择「Everyone in the tenant」会落到 `default`，保存成 `{ type: 'self' }`，因此成员列表对两种选项都显示 “Own records only”。

这是**数据写入错误**，不是翻译或渲染问题：错误的选择被真正存进了 `role_assignments.scope`。

### 10.2 修复

| 改动                           | 说明                                                                                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `toRoleScope()` 纯函数         | 从组件中抽出序列化逻辑，补上 `tenant` 分支，未知类型仍安全回退 `self`                                                                                         |
| `_scope-serialization.test.ts` | 4 项：tenant 回归、self、带 id 的多值范围、未知类型回退                                                                                                       |
| 选项文案                       | 改为 `tGeneratedValue(t.label)`，6 个选项与 6 条说明全部入目录；中文显示「仅他们自己的记录 / 租户内所有人 / 特定项目现场 / 部门或分组 / 指定人员 / 指定班组」 |
| 范围摘要                       | `Everyone in the tenant` / `Own records only` 补中文                                                                                                          |

## 11. 孤儿的答卷无法删除（EA-66D.12）

### 11.1 问题

用户报告「表单 `0c531151` 无法删除」。核查：`0c531151…` 是一条**答卷**（Arc Flash Work Plan 的草稿），不是应用。它的上级危险源评估 `803117fb…` **已被删除**。

答卷删除前会调用共享父级锁 `lockFormResponseForMutation`；父级缺失时该函数抛出 `FormResponseParentIntegrityError`，而删除动作没有捕获，整次操作失败。

### 11.2 修复

| 情况               | 行为                                                         |
| ------------------ | ------------------------------------------------------------ |
| 父级已删除/不存在  | 视为可删除：没有需要保护的父级，继续软删除                   |
| 父级仍存在但已锁定 | 拒绝并提示「上级危险源评估已锁定。请先解锁，再删除该答卷。」 |
| 其他异常           | 原样抛出，不吞错                                             |

分类逻辑抽成 `classifyParentLockError()`（`parent-gone` / `parent-locked` / `unknown`），并加 3 项单元测试。父级锁调用次数不变，仍满足 `form-response-parent-lock-contract`。

### 11.3 实测

- 部署后在 `/apps/responses` 删除 `0c531151…`：成功，行从列表消失。
- 数据库：`deleted_at` 已置位。
- 审计：`delete / Deleted Arc Flash Work Plan response`。

## 23. CI 环境差异修复（EA-66D.25）

### 23.1 `endpoint-routing` 在 CI 挂了（真实 bug）

`APP_URL` 回退逻辑（EA-66D.4 引入）在 CI 环境下吞掉了配置校验：CI 设置了 `APP_URL=http://localhost:3000`，模块加载时走“R2_ENDPOINT 不可浏览器访问 → 回退到 APP_URL”分支，把 `rawPublicEndpoint` 换成了 APP_URL（纯 origin），于是 `assertS3Origin` 永不抛错——带 path prefix 的坏 `R2_ENDPOINT` 也能加载成功，fail-fast 被架空。
