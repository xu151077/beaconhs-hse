## PD-01：F2 通用 API site/self 二次可见性

**当前行为**

- 通用 API（`/api/v1/*`）使用 Tenant-level Credential；UI 使用 `moduleScopeWhere`（site/self）。
- 已实现：租户隔离——`ctx.tenantId` 谓词（写路径 19 处）+ RLS + 请求体伪造 `tenantId` 被服务端上下文覆盖。
- 未实现：site/self 二次可见——API Key 目前可见/可写租户内全部记录。

**选项**

| 选项                | 含义                                                                       | 代价                                       | 风险                                           |
| ------------------- | -------------------------------------------------------------------------- | ------------------------------------------ | ---------------------------------------------- |
| A（维持现状）       | Tenant-level Credential 保持租户内全量                                     | 无                                         | 租户内越权面不变；需在文档中明示为已知产品边界 |
| B（复用 RoleScope） | 为 API Credential 增加 scope 列，复用现有 `RoleScope` + `moduleScopeWhere` | 需 API Key schema 变更 + 迁移 + 全写面回归 | 若另建判断逻辑会形成平行权限系统，须禁止       |
| C（分阶段）         | 先只读面加 scope，写面维持租户级                                           | 中等                                       | 读写语义不一致，需明确定义                     |

**影响 API**：`incidents / corrective_actions / inspection_records / documents / equipment / ppe / training` 及 builder 响应。
**受影响资产**：`api_keys`（当前无 scope 列）、`PERMISSION_CATALOGUE`、`RoleScope` 六变体（无 project/org-unit）。

**工程建议（非决定）**：选 A + 书面留痕；若未来选 B，必须复用 `RoleScope` 与现有权限目录，并补齐迁移/回归/文档，不新增平行权限系统。
**未决期间的边界**：通用 API 仍是租户级主体，这是**已知产品边界**，不得在报告或对外说明中表述为「已实现 site/self」。

## PD-02：审计历史回溯

**当前行为**

- `audit_log`：强制 RLS `tenant_isolation` + `audit_log_immutable_trigger`（app/super UPDATE/DELETE 被拒；TRUNCATE 由权限撤销控制）。
- app/super 仅 `SELECT, INSERT`；backup 仅 `SELECT`；owner 为唯一管理例外。
- 审计行只能在其所属租户上下文内读取。

**选项**

| 选项              | 含义                                  | 代价                                     | 风险                                            |
| ----------------- | ------------------------------------- | ---------------------------------------- | ----------------------------------------------- |
| A（维持现状）     | 无跨范围回溯授权                      | 无                                       | 合规/审计岗无法查历史全貌                       |
| B（独立授权规则） | 新增受控的审计回溯角色/权限           | 需新权限键 + RLS 例外策略 + 审计自身审计 | 会扩大跨租户读取面；须评估与 RESTRICT FK 的交互 |
| C（导出替代）     | 不容许在线回溯，改由离线导出/归档满足 | 需导出链路与访问控制                     | 延迟、副本一致性                                |

**工程建议（非决定）**：选 A；若确有合规需求走 C（离线），避免在线开 RLS 例外。**不得擅自新增权限键或放宽 RLS**。
**未决期间的边界**：不存在任何跨租户/跨范围审计查询能力。

## PD-03：A3 目标在库回填

**当前状态**

- 代码侧已具备附件删除一致性：同事务 + 四入口统一 `FOR UPDATE` 锁 + outbox 唯一约束 + worker 幂等（真 PG A–I 验证）。
- **A3 Apply 未执行、历史回填未执行**，不得标记为完成。
- 目标在库问题：`BEACONHS_CUTOVER_TARGET=beaconhs-dev` 目标在库未定位（见 `TEST_HOST_A3_FORENSIC_AUDIT.md` 指纹追溯）。

**选项**

| 选项                  | 含义                                                      | 代价             | 风险                                             |
| --------------------- | --------------------------------------------------------- | ---------------- | ------------------------------------------------ |
| A（不回填，接受现状） | 历史孤儿/删标记数据保持                                   | 无               | 历史数据风险敞口存在；未来路径已被代码覆盖       |
| B（定位后回填）       | 先确定目标在库 → 备份 → 核对 → 事务回填 → 验证 → 回滚预案 | 高（需停机窗口） | 需先解决「目标在库未定位」；误操作会污染生产数据 |
| C（仅审计不修改）     | 只读盘点历史异常，形成清单                                | 低               | 不消除风险                                       |

**执行 B 的硬性前置**（缺一不可）：

1. 明确目标在库与租户范围（当前未定位）
2. 全量备份（DB + 对象存储）+ 恢复演练记录
3. 数据核对脚本（差异行数、孤儿定义、幂等键）
4. 事务化回填 + 逐批校验 + 可回滚方案
5. 停机窗口与负责人

**工程建议（非决定）**：在目标在库未定位前维持 A，最多做 C；**禁止**在未满足前置条件时执行 Apply。
**未决期间的边界**：历史数据未修复，A3 相关文档一律标注「未执行」。
